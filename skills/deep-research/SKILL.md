# deep-research

把"查资料"变成可复用的标准流程，避免每次重新摸索检索策略。

## Overview

适用于任何需要**外部事实**支撑的任务：技术选型对比、市场调研、事实核查。
不适用于纯推理、代码生成或对已有文件的分析。

## Instructions

### 1. 拆检索角度

把研究问题拆成 3-5 个**互补**角度，而不是同一件事的近义词：

| 角度 | 示例（问题："XXX 框架是否适合生产环境"） |
|---|---|
| 官方立场 | 官方文档的架构说明与适用边界 |
| 实践反馈 | 生产案例、性能报告、迁移经验 |
| 反面对照 | 已知缺陷、issue 讨论、替代方案 |
| 量化指标 | 吞吐、延迟、内存、成本数字 |

### 2. 逐条检索

用 `internet_search` 逐条查询。**每次查询换一个角度**，不要重复搜索同一关键词。

### 3. 落盘规范

每条有价值的结论调用 `write_finding`，参数约定：

| 参数 | 要求 |
|---|---|
| `topic` | 一句话结论主题，会转成文件名 |
| `summary` | 200 字以内，只写结论本身 |
| `sources` | 来源 URL，多个用换行分隔 |

**只落盘结论，不落盘原文**。原文片段留在检索结果里，需要时再回查。

### 4. 引用格式

输出中引用来源统一写成 `[标题](URL)`。无法给出来源的判断，必须标注"待验证"。

## 边界情况

- **检索无结果**：换更宽泛的关键词再试一次；仍无结果就如实写进信息缺口，不要编造。
- **来源互相冲突**：两条都保留，并在输出中指出冲突，不要单方面采信一条。
- **内容超出摘要**：需要细节时用工具重新检索或读取原文，不要凭印象扩写。
