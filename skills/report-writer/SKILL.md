# report-writer

统一所有交付物的版式，保证同一份项目里产出的简报长得一样、读起来一致。

## Instructions

### 1. 固定版式

```markdown
# <标题>

## 摘要
3-5 句话讲清结论是什么、依据是什么。

## 关键发现
- 发现一（附来源）
- 发现二（附来源）

## 风险与不确定性
- 列出结论的适用边界、未验证项、数据时效

## 建议下一步
- 2-4 条可执行动作，不要写成空泛的"继续关注"
```

### 2. 写作规则

| 规则 | 说明 |
|---|---|
| 结论先行 | 每段第一句就是结论，后面才是依据 |
| 小标题自解释 | 小标题单独看也要能读懂 |
| 不重复原文 | 材料里的原文只在必要时引用，且必须标注来源 |
| 控制篇幅 | 简报 ≤ 800 字；超出说明信息未收敛，应回到分析阶段 |
| 不引入新事实 | 只能使用已落盘材料中出现的事实 |

### 3. 落盘约定

最终产物写入 `/workspace/report.md`，同时把正文作为返回值交给主 Agent。

## 边界情况

- **材料不足**：不要硬写。在"风险与不确定性"里说明缺口，并在返回内容中提示主 Agent 补充资料。
- **存在冲突结论**：正文中并列呈现两种说法及各自来源，不做单方面采信。
- **要求超出篇幅**：优先保留"摘要"与"关键发现"，压缩细节描述。
